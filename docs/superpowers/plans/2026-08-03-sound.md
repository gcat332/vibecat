# Sound Implementation Plan (Plan 6.2, §12)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Five synthesised alert cues that fire when the island's state becomes
news, ported from the working synth in `island-motion.html` rather than designed
from §12's summary table.

**Architecture:** A cue is a list of notes; a note is a pure function from sample
index to a `Float`. Everything that decides *what* a cue sounds like — waveform,
envelope, pitch bend, the note tables — is a pure function testable without an
audio device. `AVAudioEngine` appears once, in a deliberately thin pump whose
only job is to hand an already-rendered buffer to the hardware. The trigger is a
pure function of (event, store-before, store-after), hung off `AppModel`'s
existing callback pattern.

**Tech Stack:** Swift 6, `AVFoundation` (`AVAudioEngine` + `AVAudioPlayerNode`),
`Intents` (`INFocusStatusCenter`) for Do Not Disturb. All system frameworks —
**no package may be added.**

## What already exists, and what does not

Verified by reading the tree, not assumed:

| Thing | State |
|---|---|
| Any audio at all in `Sources/` | **None.** `AVAudio`, `NSSound`, `AudioToolbox`, `oscillator` — zero hits |
| `AppModel.onChange` / `onQuestion` | Exist. Explicit callbacks, deliberately not Observation — see the comment at `AppModel.swift:14-29` |
| `SessionStore` | `Equatable` value type; `aggregate`, `counts: [SessionState: Int]`, `sessions` |
| `SessionState` | `idle, running, waiting, failed` — **no `done` case** |
| `SessionState.init(kind:)` | Maps `.done` **and** `.idle` to `.idle` |
| `IslandState` | `dormant, idle, running, waiting, failed` — no multiplicity, no `done` |
| Settings persistence | **None.** No `UserDefaults` wrapper anywhere. Plan 6.4 owns it |

### Three facts that decide the design

1. **`done` does not survive into any state.** `SessionState.init(kind:)`
   collapses `.done` into `.idle`, so nothing downstream can tell "finished" from
   "was never busy". §12's Finished cue therefore keys on `VibeEvent.Kind.done`,
   off the event, while the other three key on a state change. This is not a
   shortcut; it is the only place the information exists.
2. **The mockup's trigger is a change of *presented* state, and its presented
   state includes multiplicity.** `paint()` at line 957 is
   `if (!quiet && state !== island.dataset.state) cue(state)`, over the state
   list `['dormant','working','multi','done','ask','askmulti','error','list']`.
   `ask` and `askmulti` are *different states* there, so a second session asking
   is a state change and does cue. Our `IslandState` cannot express that, so this
   plan introduces `CueKey` — the mockup's vocabulary, minus the states that have
   no cue.
3. **Web Audio's `square` and `sawtooth` are band-limited; a naive Swift square
   is not.** `done` holds G6 = 1568 Hz; a naive square's harmonics run past
   Nyquist and fold back as audible inharmonic hash the prototype does not have.
   Additive synthesis truncated below Nyquist is both exactly band-limited and a
   pure function of an analytic series, which is the only reason any of this is
   testable.

## The five written decisions

Recorded here so nobody "corrects" them later, and so the spec correction in
Task 7 has something to cite. **Three were written before execution; 4 came out
of execution and 5 out of the final fix round.** The whole-branch review found
4 documented at length in its own source and in two task reports, and this list
still saying "three" — which is the failure mode this section exists to prevent,
one level up.

1. **§12's Voice column omits the detuned twin on two cues.** The table gives
   `ask` "pulse, detuned twin" but gives `askmulti` and `Finished` bare "pulse".
   The mockup passes `duty:8` to every note of `askmulti` and `duty:6` to every
   note of `done` — both get the twin. **The mockup wins**, per the standing rule
   that the prototype is the authority on appearance; the table's column is
   shorthand that lost a parameter. Same for per-note gain, which the table
   cannot express at all: `done`'s held G6 and all four notes of `error` are
   `.06`, and `meow` is `.09`, against the `.07` default.
2. **A cue fires when demand *increases*, never when it falls.** The mockup
   cues on any change of presented state, so answering one of two questions takes
   it `askmulti → ask` and beeps at you for having just done the right thing.
   Clicking buttons in a browser makes that invisible; a real person answering a
   real question would be interrupted by a sound congratulating them. **We fire
   only when the waiting count rises, or when `waiting`/`failed` is newly
   reached.** Written down because it is a real divergence from line 957.
3. **Only the Chiptune pack and Silent exist.** `settings.html` offers four packs
   (Chiptune, Soft, System, Silent) and per-cue alternatives (`Blip`, `Meow`,
   `None`), but **no file in this repo defines what Soft, System or Blip sound
   like.** `Meow` is defined and is included. Inventing the rest would be
   inventing design; they are out of scope until someone specifies them, and
   `SoundPack` is an enum so adding one later is additive.
4. **A note shorter than the 6ms attack has its attack shortened to half its
   duration.** Added during Task 2 (`ToneEnvelope.swift:27`,
   `min(Self.attack, duration / 2)`); the prototype has no such clamp. Web Audio
   simply stops the oscillator mid-ramp, which leaves the note at a non-zero
   amplitude — the same audible click the `0.0001` floor exists to prevent,
   arriving by another route. **No cue in the chiptune pack is anywhere near this
   short** (the shortest is 0.09s), so it never engages for a real note; it exists
   so a future pack cannot produce a click by accident. Documented in the source
   and in Task 2's report from the day it was written, and missing from this list
   until 2026-08-03.
5. **Cues play serially, and a cue more than 1.0s behind is dropped rather than
   queued.** The prototype's `cue()` builds fresh oscillators per call
   (`island-motion.html:914-917`), each connected straight to `ac.destination`, so
   overlapping cues *mix*. `AVAudioPlayerNode.scheduleBuffer` queues them instead.
   **Serial stays** — mixing needs a mixer graph and a player node per voice, real
   machinery for a rare case, and two chiptune alerts summed at full gain are
   louder than either where queued ones stay at the level someone chose. What
   could not stay is the *unbounded* queue: N events in a burst put the Nth alert
   0.6…0.9s × (N−1) after the thing it announces, and `.done` bypasses every
   state-change guard so it has no rate limit of its own. The bound is wall-clock
   rather than a count of outstanding buffers, so a missed completion callback
   cannot wedge it at "full" and silence the app for the session. See
   `SoundPlayer.maximumBacklog`.

## Task 1: Band-limited waveforms

**Files:**
- Create: `Sources/VibeCatUI/Sound/Waveform.swift`
- Test: `Tests/VibeCatUITests/WaveformTests.swift`

**Interfaces:**
- Consumes: nothing.
- Produces: `public enum Waveform: String, Sendable, CaseIterable { case square, sawtooth, triangle }`
  with `public func sample(phase: Double, harmonics: Int) -> Double` and
  `public static func harmonicCount(frequency: Double, sampleRate: Double) -> Int`.
  `phase` is in cycles (`0…1` is one period, and values outside that are legal).

Why additive rather than the obvious `phase < 0.5 ? 1 : -1`: a naive square at
G6 = 1568 Hz emits harmonics at 4704, 7840 … past 22050 Hz, and every one above
Nyquist folds back down as an inharmonic tone that is not in the prototype.
Truncating the series below Nyquist is exactly band-limited by construction.

The analytic series, with the standard coefficients:

- square: `(4/π) · Σ_{n odd} sin(2πnφ)/n`
- sawtooth: `(2/π) · Σ_{n≥1} (−1)^(n+1) · sin(2πnφ)/n` — rising ramp, matching
  Web Audio's `'sawtooth'`
- triangle: `(8/π²) · Σ_{k odd} (−1)^((k−1)/2) · sin(2πkφ)/k²`

We deliberately do **not** normalise the peak to 1.0. A truncated series
overshoots (Gibbs) to about 1.09 for a square, so a `gain` of `.07` produces a
peak near `.076` — roughly a factor of ten of headroom before clipping.
Normalising would cost a peak search per note and buy nothing audible.

*(An earlier draft of this plan said "three orders of magnitude below clipping"
here and in Task 1's doc comment. It is one. Corrected because a wrong number in
a comment is worse than no comment — the next person reasons from it.)*

```swift
import Foundation

/// The three oscillator shapes §12 calls for, band-limited by construction.
///
/// Built by summing the shape's own Fourier series and stopping below Nyquist,
/// rather than by the obvious `phase < 0.5 ? 1 : -1`. A naive square at G6
/// (1568Hz, which `done` holds for 0.46s) puts harmonics at 4704, 7840, 10976 …
/// well past 22050Hz, and every one above it folds back down as an inharmonic
/// tone. The prototype does not have that hash because Web Audio's `'square'`
/// is band-limited too.
///
/// The series are the standard ones and are **not** peak-normalised. A truncated
/// square overshoots to about 1.09 (Gibbs), so the loudest note this project
/// plays — gain `.09` — peaks near `.098`, leaving roughly a factor of ten of
/// headroom. Normalising would cost a peak search per note and change nothing
/// anybody can hear.
public enum Waveform: String, Sendable, CaseIterable {
    case square, sawtooth, triangle

    /// `phase` is in cycles: `0…1` is one period. Values outside that are legal
    /// and periodic, which is what lets a caller integrate phase across a whole
    /// note without wrapping it.
    public func sample(phase: Double, harmonics: Int) -> Double {
        let ω = 2 * Double.pi * phase
        var sum = 0.0
        switch self {
        case .square:
            for n in stride(from: 1, through: harmonics, by: 2) {
                sum += sin(ω * Double(n)) / Double(n)
            }
            return sum * 4 / .pi
        case .sawtooth:
            for n in 1...max(1, harmonics) {
                let sign = n.isMultiple(of: 2) ? -1.0 : 1.0
                sum += sign * sin(ω * Double(n)) / Double(n)
            }
            return sum * 2 / .pi
        case .triangle:
            for k in stride(from: 1, through: harmonics, by: 2) {
                let sign = ((k - 1) / 2).isMultiple(of: 2) ? 1.0 : -1.0
                sum += sign * sin(ω * Double(k)) / Double(k * k)
            }
            return sum * 8 / (.pi * .pi)
        }
    }

    /// How many harmonics fit below Nyquist. Never zero: a note that renders
    /// silence is a defect, not graceful degradation.
    public static func harmonicCount(frequency: Double, sampleRate: Double) -> Int {
        guard frequency > 0 else { return 1 }
        return max(1, Int((sampleRate / 2) / frequency))
    }
}
```

## Task 2: The envelope

**Files:**
- Create: `Sources/VibeCatUI/Sound/ToneEnvelope.swift`
- Test: `Tests/VibeCatUITests/ToneEnvelopeTests.swift`

**Interfaces:**
- Consumes: nothing.
- Produces: `public struct ToneEnvelope: Sendable` with
  `public static let attack: TimeInterval = 0.006`,
  `public static let floor: Double = 0.0001`, and
  `public static func amplitude(at t: TimeInterval, duration: TimeInterval, gain: Double) -> Double`.

The mockup's envelope, verbatim from lines 873–875:

```js
amp.gain.setValueAtTime(0.0001, t0);
amp.gain.exponentialRampToValueAtTime(gain, t0 + .006);
amp.gain.exponentialRampToValueAtTime(0.0001, t0 + dur);
```

Web Audio's `exponentialRampToValueAtTime` between `(t₁,v₁)` and `(t₂,v₂)` is
`v(t) = v₁ · (v₂/v₁)^((t−t₁)/(t₂−t₁))`. So:

- `0 ≤ t < 0.006`: `floor · (gain/floor)^(t/0.006)`
- `0.006 ≤ t ≤ duration`: `gain · (floor/gain)^((t−0.006)/(duration−0.006))`

The `0.0001` is not a magic number and must not be "cleaned up" to zero: an
exponential ramp cannot reach or cross zero, which is why Web Audio's own idiom
starts and ends at a small positive floor. Ending at zero instead produces a
click; that is the whole reason the prototype has it.

```swift
import Foundation

/// §12's "hard attack (`6ms`), exponential decay — the whole character of the
/// era", as the prototype actually implements it at `island-motion.html:873-875`.
///
/// Web Audio's `exponentialRampToValueAtTime` between `(t₁,v₁)` and `(t₂,v₂)` is
/// `v₁ · (v₂/v₁)^((t−t₁)/(t₂−t₁))`, and that is what these two branches are.
public struct ToneEnvelope: Sendable {
    /// §12's 6ms. Hard enough to read as an attack rather than a swell.
    public static let attack: TimeInterval = 0.006

    /// **Not zero, and not a rounding artefact.** An exponential ramp cannot
    /// reach or cross zero — `v₁ · (0/v₁)^x` is zero everywhere — so Web Audio's
    /// own idiom ramps between small positive values. Ending a note at true zero
    /// instead of gliding to a floor is an audible click at the release. Do not
    /// "simplify" this away.
    public static let floor: Double = 0.0001

    public static func amplitude(at t: TimeInterval, duration: TimeInterval, gain: Double) -> Double {
        guard t > 0 else { return floor }
        guard t < duration else { return floor }
        // Clamped, so a note shorter than 6ms compresses its attack instead of
        // overrunning its own duration. Unclamped, a 4ms note would stop
        // partway up the ramp at a non-zero amplitude — the click `floor`
        // exists to prevent, arriving by a different route. This changes nothing
        // for any real note: the shortest in the pack is 0.09s, whose half is
        // 0.045, far above 6ms.
        let attack = min(Self.attack, duration / 2)
        if t < attack {
            return floor * pow(gain / floor, t / attack)
        }
        // No guard needed on the tail: `attack <= duration/2 < duration`, so
        // `tail >= duration/2 > 0` wherever this line runs. An earlier draft had
        // a `guard tail > 0` here, which was unreachable — reaching this point
        // requires `t >= attack` and `t < duration`, which already force
        // `duration > attack`. The guard's presence was what hid the missing
        // clamp above, because the test written for it was intercepted by
        // `guard t < duration` and passed for an unrelated reason.
        let tail = duration - attack
        return gain * pow(floor / gain, (t - attack) / tail)
    }
}
```

The bend is the one piece of real maths. `note()` does
`osc.frequency.exponentialRampToValueAtTime(freq * bend, t0 + dur)`, so the
instantaneous frequency is `f(t) = f₀ · b^(t/D)`. A sample generator needs
*phase*, which is the integral:

```
φ(t) = ∫₀ᵗ f₀ · b^(τ/D) dτ = f₀ · D · (b^(t/D) − 1) / ln b        (b ≠ 1)
φ(t) = f₀ · t                                                       (b = 1)
```

Getting this wrong does not produce silence, it produces a note at the wrong
pitch — which is exactly the class of bug a listening test misses and an
analytic one catches. Note that `b = 1` and `b = 0` (the prototype's "no bend")
both mean "no ramp" and must take the linear branch.

Detune is in cents: `detuned` multiplies `f₀` by `pow(2, cents/1200)`.

```swift
import Foundation

/// The note table from `island-motion.html:891-893`, verbatim.
///
/// Equal temperament above A5 = 880Hz. Eight of the prototype's entries have no
/// cue that uses them (`d5 f5 a5 b5 d6 f4 e4 g3`) — they are there because the
/// prototype's own comment says a pack "retunes per state for free", and
/// deleting them would remove the scaffolding for the alternative packs
/// `settings.html` offers.
public enum Pitch {
    public static let c5 = 523.25, d5 = 587.33, e5 = 659.25, f5 = 698.46
    public static let g5 = 783.99, a5 = 880.0,  b5 = 987.77
    public static let c6 = 1046.5, d6 = 1174.7, e6 = 1318.5, g6 = 1568.0
    public static let g4 = 392.0,  f4 = 349.23, e4 = 329.63
    public static let c4 = 261.63, eFlat4 = 311.13, bFlat3 = 233.08, g3 = 196.0
}

/// One note of a cue. Mirrors the prototype's
/// `note(freq, at, dur, {type, gain, bend, duty})` argument for argument, so a
/// reader can diff a cue against `island-motion.html:894-912` by eye.
public struct Note: Sendable, Equatable {
    public let frequency: Double
    /// Offset from the start of the cue, not from the note before it.
    public let at: TimeInterval
    public let duration: TimeInterval
    public let waveform: Waveform
    public let gain: Double
    /// The prototype's `bend`: the frequency ramps exponentially to
    /// `frequency * bend` across the note. **`0` means no bend**, which is how
    /// the prototype spells it — see `phase(at:detuned:)`.
    public let bend: Double
    /// The prototype's `duty`, in cents. `0` means no twin.
    public let detuneCents: Double

    public init(_ frequency: Double, at: TimeInterval, _ duration: TimeInterval,
                waveform: Waveform = .square, gain: Double = 0.07,
                bend: Double = 0, detuneCents: Double = 0) {
        self.frequency = frequency
        self.at = at
        self.duration = duration
        self.waveform = waveform
        self.gain = gain
        self.bend = bend
        self.detuneCents = detuneCents
    }

    public var end: TimeInterval { at + duration }

    /// Phase in cycles, `t` measured from the note's own onset.
    ///
    /// An unbent note is just `f·t`. A bent one has an instantaneous frequency
    /// of `f₀·b^(t/D)` — Web Audio's `exponentialRampToValueAtTime` — and a
    /// sample generator needs the integral of that, not the value:
    ///
    ///     φ(t) = f₀·D·(b^(t/D) − 1) / ln b
    ///
    /// Using the frequency directly instead of its integral does not fail
    /// loudly; it plays the note at the wrong pitch, which is why this is
    /// asserted by differentiating rather than by listening.
    ///
    /// **`bend == 0` and `bend == 1` both mean "no ramp".** The prototype
    /// spells "no bend" as `0`, and `ln 0` is `-∞`: applying the closed form to
    /// it would make every plain note in the pack `NaN`, which renders as
    /// silence — and silence passes any test that only counts samples.
    public func phase(at t: TimeInterval, detuned: Bool) -> Double {
        let f0 = detuned ? frequency * pow(2, detuneCents / 1200) : frequency
        guard bend > 0, bend != 1, duration > 0 else { return f0 * t }
        return f0 * duration * (pow(bend, t / duration) - 1) / log(bend)
    }
}
```

```swift
/// §12's five cues. `ask`, `askMulti`, `done` and `error` fire from a state
/// change; `meow` never does — it exists for the Settings sheet's per-cue
/// alternatives and for the prototype's own meow button.

/// A pack is "a handful of oscillator settings rather than a folder of files"
/// (§12), which is why this is an enum returning arrays rather than a resource
/// bundle.
///
/// **Only `chiptune` and `silent` exist, deliberately.** `settings.html` offers
/// Chiptune / Soft / System / Silent and per-cue alternatives Blip / Meow /
/// None, but nothing in this repo defines what Soft, System or Blip sound like —
/// no frequencies, no waveforms, nothing. Inventing them would be inventing
/// design rather than implementing it. Adding a case later is additive.
public enum SoundPack: String, Sendable, CaseIterable {
    case chiptune, silent

    /// gain and detune below is from that block. §12's durations are the
    /// arithmetic consequence of the last note's `at + duration` and are
    /// asserted in `everyCueLastsWhatTheSpecTableSays`.
    public func notes(for cue: Cue) -> [Note] {
        switch self {
        case .silent: return []
        case .chiptune: break

        switch cue {

        case .ask:

                    Note(Pitch.c6, at: 0.10, 0.11, detuneCents: 8),
                    Note(Pitch.e6, at: 0.20, 0.11, detuneCents: 8),
                    Note(Pitch.c6, at: 0.30, 0.36, detuneCents: 8)]
        // The same figure doubled before it resolves — more voices, more urgency.

                    Note(Pitch.g5, at: 0.20, 0.10, detuneCents: 8),

                    Note(Pitch.bFlat3, at: 0.45, 0.46, waveform: .sawtooth, gain: 0.06,
                         bend: 0.80)]
        // Two syllables of pitch-bent triangle. 600 and 1040Hz are not named
```

```swift
import Foundation

/// A cue, as samples. Pure, so the thing that decides what VibeCat sounds like
/// is testable without an audio device — which matters more here than usual: an
/// `AVAudioSourceNode` render callback, like a `Canvas` renderer, never runs
/// during a property read, so a test that only touched the player would prove
/// nothing at all.
public struct CueRenderer: Sendable {
    /// The prototype stops each oscillator at `t0 + dur + .02`, so a rendered
    /// cue carries the same 20ms of release past its last note.
    public static let releaseTail: TimeInterval = 0.02

    public static func render(_ cue: Cue, settings: SoundSettings,
                             sampleRate: Double) -> [Float] {
        guard settings.enabled else { return [] }
        let notes = settings.pack.notes(for: cue)
        guard let last = notes.map(\.end).max() else { return [] }

        let frameCount = Int((last + releaseTail) * sampleRate)
        var buffer = [Float](repeating: 0, count: frameCount)

        for note in notes {
            let start = Int(note.at * sampleRate)
            let count = Int(note.duration * sampleRate)
            let harmonics = Waveform.harmonicCount(frequency: note.frequency,
                                                   sampleRate: sampleRate)
            // A twin's own frequency is higher, so it fits fewer harmonics.
            // Reusing the principal's count would push its top partial past
            // Nyquist — the exact aliasing `Waveform` exists to avoid.
            let twinHarmonics = note.detuneCents == 0 ? harmonics
                : Waveform.harmonicCount(frequency: note.frequency * pow(2, note.detuneCents / 1200),
                                         sampleRate: sampleRate)

            for i in 0..<count {
                let frame = start + i
                guard frame < frameCount else { break }
                let t = Double(i) / sampleRate
                let amp = ToneEnvelope.amplitude(at: t, duration: note.duration, gain: note.gain)
                var value = note.waveform.sample(phase: note.phase(at: t, detuned: false),
                                                 harmonics: harmonics) * amp
                if note.detuneCents != 0 {
                    // The prototype's second pulse channel: same shape, detuned,
                    // at 60% of the principal's gain — thickening the tone
                    // rather than doubling its amplitude.
                    let twinAmp = ToneEnvelope.amplitude(at: t, duration: note.duration,
                                                         gain: note.gain * 0.6)
                    value += note.waveform.sample(phase: note.phase(at: t, detuned: true),
                                                  harmonics: twinHarmonics) * twinAmp
                }
                buffer[frame] += Float(value * settings.volume)
            }
        }
        return buffer
    }
}
```

`CueKey` is the mockup's presented-state vocabulary reduced to the states that

what makes a second session asking a change worth announcing.

The rule, in order:

1. `event.kind == .done` → `.done`. **From the event, not from state**:
   `SessionState.init(kind:)` maps `.done` to `.idle`, so by the time the store
   has been updated the fact that anything finished no longer exists anywhere.
2. Otherwise compare `CueKey(store: before)` with `CueKey(store: after)`. If they
   are equal, nothing fires.
3. `.failed` → `.error`.
4. `.ask` or `.askMulti` → the matching cue, **but only if demand rose**. Going
   `askMulti → ask` means somebody answered one of two questions; the mockup
   cues there (line 957 fires on any change) and we deliberately do not. Written
   decision 2 in this plan's header.

```swift
import Foundation
import VibeCatCore

/// The island's presented state, reduced to what has a sound.
///
/// The prototype cues on a change of its own presented state
/// (`island-motion.html:957`), over the vocabulary
/// `['dormant','working','multi','done','ask','askmulti','error','list']`. Two
/// of those matter here and `IslandState` cannot express either: `ask` and
/// `askmulti` are **different states** there, so a second session asking is a
/// change; and `done` is a state there but not here, because
/// `SessionState.init(kind:)` folds `.done` into `.idle`.
///
/// `dormant`, `idle` and `running` collapse into `quiet` — the prototype has no
/// `CUES` entry for `dormant`, `working`, `multi` or `list` either, so its
/// `cue()` returns early for all four.
public enum CueKey: Equatable, Sendable {
    case quiet
    case ask, askMulti, failed

    public init(store: SessionStore) {
        guard !store.sessions.isEmpty else { self = .quiet; return }
        switch store.aggregate {
        case .waiting: self = (store.counts[.waiting] ?? 0) > 1 ? .askMulti : .ask
        case .failed:  self = .failed
        case .running, .idle: self = .quiet
        }
    }

    /// How many agents this key says are waiting on a person: 0, 1, or "more
    /// than one". Used to tell a rise in demand from a fall.
    var waitingRank: Int {
        switch self {
        case .askMulti: 2
        case .ask:      1
        case .quiet, .failed: 0
        }
    }
}

/// Which cue an event earns, if any.
public struct CueSelector: Sendable {
    public static func cue(for event: VibeEvent,
                           before: SessionStore, after: SessionStore) -> Cue? {
        // A finished run is the one thing that cannot be read off the state.
        // `SessionState.init(kind:)` maps `.done` to `.idle`, so once `after`
        // exists there is no trace of anything having completed — and §4.2's
        // worst-state-wins governs what the island *displays*, not what
        // happened, so a finish while another agent waits is still news.
        if event.kind == .done { return .done }

        let old = CueKey(store: before), new = CueKey(store: after)
        guard old != new else { return nil }

        switch new {
        case .failed: return .error
        case .ask, .askMulti:
            // Only a rise in demand is news. The prototype cues on any change,
            // so answering one of two questions takes it `askmulti → ask` and
            // sounds the alert again — congratulating you for the thing you just
            // did. Clicking buttons in a browser hides that; a person being
            // interrupted would not miss it.
            guard new.waitingRank > old.waitingRank else { return nil }
            return new == .askMulti ? .askMulti : .ask
        case .quiet:
            return nil
        }
    }
}
```

### The Do Not Disturb problem, stated honestly

§12 says "Respects Do Not Disturb". macOS 14 has exactly one supported way to
read that: `INFocusStatusCenter` from the `Intents` framework, which needs
`NSFocusStatusUsageDescription` in `Info.plist` and the user's authorization.
Reading `~/Library/DoNotDisturb/DB/Assertions.json` is the widely-copied
alternative and is unsupported — it has changed shape between OS releases, and
this project's standing rule is that an unmeasured platform assumption is
labelled as such rather than shipped as fact.

That makes DND **a fourth permission**, and §15 lists three (Automation,
Notifications, Screen Recording). So:

- The gate is a protocol with two implementations, so the mechanism can be
  replaced without touching anything that decides what a cue sounds like.
- When authorization is `.notDetermined` or `.denied`, `isQuiet` is `false` —
  sound plays. A user who turned sound on and never answered a permission prompt
  should hear their agents, and §14's Notifications section already carries a
  "Permissions" row for surfacing the state. Plan 6.4 wires that row.
- **The behaviour of `INFocusStatusCenter` from this bundle is unverified**, and
  a bare `swift run` cannot verify it: without a bundle identifier, TCC
  attributes the request to the launching terminal and the grant dies as soon as
  the app is opened any other way. Step 8 below is the hardware check, and its
  result goes in the report either way.

```swift
import Foundation
import AVFoundation

/// The only file in this plan that touches an audio device.
///
/// Deliberately thin. Everything that decides what VibeCat sounds like — the
/// waveforms, the envelope, the note tables, which cue fires — is a pure
/// function in a neighbouring file, because an audio render path is invisible to
/// this project's tests in exactly the way a `Canvas` renderer is: the work
/// happens somewhere no `#expect` can reach. `buffer(for:)` is exposed so the
/// gating decisions *are* testable; the engine below it is verified by
/// listening, on hardware, from a real bundle.
@MainActor public final class SoundPlayer {
    public var settings: SoundSettings
    private let quietHours: QuietHours
    private let engine = AVAudioEngine()
    private let node = AVAudioPlayerNode()
    private var started = false

    public init(settings: SoundSettings = SoundSettings(),
                quietHours: QuietHours = NeverQuiet()) {
        self.settings = settings
        self.quietHours = quietHours
    }

    /// `nil` when nothing should be heard: sound off, the pack is silent, or the
    /// machine is asking for quiet and the user left that switch on.
    public func buffer(for cue: Cue) -> [Float]? {
        if settings.quietDuringDoNotDisturb && quietHours.isQuiet { return nil }
        let samples = CueRenderer.render(cue, settings: settings,
                                         sampleRate: outputSampleRate)
        return samples.isEmpty ? nil : samples
    }

    private var outputSampleRate: Double {
        let rate = engine.outputNode.outputFormat(forBus: 0).sampleRate
        // A zero here means no output device is attached, which happens in CI
        // and on a headless machine. 44.1k keeps the pure renderer's arithmetic
        // well-defined; nothing will be heard either way.
        return rate > 0 ? rate : 44_100
    }

    public func play(_ cue: Cue) {
        guard let samples = buffer(for: cue) else { return }
        let format = engine.outputNode.outputFormat(forBus: 0)
        guard format.sampleRate > 0,
              let pcm = AVAudioPCMBuffer(pcmFormat: format,
                                         frameCapacity: AVAudioFrameCount(samples.count))
        else { return }
        pcm.frameLength = AVAudioFrameCount(samples.count)
        // Mono content into however many channels the device has: §12's cues
        // are a chip's monophonic voice, and panning one would be an invention.
        for channel in 0..<Int(format.channelCount) {
            guard let data = pcm.floatChannelData?[channel] else { continue }
            samples.withUnsafeBufferPointer { data.update(from: $0.baseAddress!, count: samples.count) }
        }
        start()
        node.scheduleBuffer(pcm, completionHandler: nil)
        node.play()
    }

    private func start() {
        guard !started else { return }
        engine.attach(node)
        engine.connect(node, to: engine.mainMixerNode,
                       format: engine.outputNode.outputFormat(forBus: 0))
        do { try engine.start(); started = true }
        catch {
            // Fail silent, never fatal. Nothing in §12 is worth taking the
            // island down for, and §2.3's fail-open reflex applies here too:
            // the absence of a sound must never be the absence of the app.
            started = false
        }
    }
}
```

Two of the fixes are worth reading for the trap rather than the outcome. The first
differential pitch test compared `.done` against `.done` an octave up, and the

envelope decays to 0.0001 across the same span, so a large difference in phase is a
vanishing one in samples.
